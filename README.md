# hxwl-06 显微镜玻片观察（可追溯流程版）

样本 → 染色批次版本/标尺 → 观察记录 → 复核任务 → 操作留痕的完整追溯链。

## 技术栈

React 19 + Vite + TypeScript + 纯本地持久化（localStorage：主存储 + 完整检查点 + 只追加审计流）

## 本地运行

```bash
npm install
npm run dev        # 开发端口 5106
npm run typecheck  # 类型检查
npm run verify     # 端到端业务规则验证（37 项断言）
npm run build
```

## 角色与权限

- **学生**：只能以本人名义提交观察结论；选择他人名义提交视为越权代写，直接拒绝并留痕。
- **教师**：复核按「染色批次 × 放大倍数」分组进行；已复核结论的依据变更产生复议任务，可选择维持（保留当时依据）或修订（原依据标记为历史并按新依据重算后重新复核）。
- **管理员**：登记玻片、补核旧数据、调整批次有效期/标尺版本、导入记录、检查点与故障演练。

## 统一处理状态

明细、待办、统计共用同一套状态口径：

| 状态 | 含义 |
| --- | --- |
| 待核 | 旧数据/导入记录缺染色批次版本，管理员核对前不进入复核 |
| 待复核 | 先到结论已生效，等待教师复核 |
| 已复核 | 复核通过，依据（批次版本、标尺、有效期、倍数、结论）已冻结 |
| 已退回 | 复核退回 |
| 失效重算中 | 批次依据变更，结论立即失效并重新计算 |
| 已失效 | 重算后依据不成立（如观察日期不在批次有效期内） |
| 冲突保留 | 同玻片后到提交：内容保留、显示冲突、先生效结论不变 |

## 核心业务规则

- **先到生效 / 后到冲突**：同一玻片存在生效结论时，新提交保存为「冲突保留」并指向先到记录；先生效记录失效后，最早的冲突保留记录自动释放进入复核。
- **批次变更级联**：管理员调整有效期或标尺版本即升批次版本——
  - 未复核结论立即「失效重算」：观察日期不在新有效期内则置已失效，否则按新标尺重算测量值并重新入复核队列，原任务取消；
  - 已复核结论状态不变，复核当时依据冻结保留，同时逐条列出复议项，交教师复议。
- **幂等提交**：观察者 + 玻片 + 倍数 + 内容指纹相同的重复提交（含导入文件内重复）不生成第二条记录，只记一条 `duplicate` 留痕。
- **事务与恢复**：提交按「写主存储 → 校验和回读 → 通过后推进完整检查点」执行；写入截断或导入提交失败时，整体回滚到最近完整检查点，业务留痕仅在提交成功后写入，回滚单独记 `recovered` 留痕。主存储损坏时下次启动自动从检查点恢复。
- **旧数据待核**：缺批次版本的历史记录与导入记录一律先置「待核」，在明细、待办、统计中显示同一状态；补核时若观察日期超出当前批次有效期，与重算同口径直接置已失效。

## 存储结构（localStorage）

- `hxwl06.state.v1`：主业务数据（校验和信封）
- `hxwl06.checkpoint.v1`：最近一次完整成功状态的检查点（同信封结构）
- `hxwl06.audit.v1`：只追加操作留痕（成功/拒绝/失败/恢复/重复，保留最近 300 条）

## 目录

- `src/types.ts` 领域模型
- `src/domain.ts` 纯函数规则（状态口径、分组、测量换算、冲突选择）
- `src/store.ts` 权限、幂等、冲突、批次级联、复议、事务提交
- `src/storage.ts` 校验和信封、检查点、故障注入与恢复
- `src/seed.ts` 演示数据（含旧数据、已复核、冲突等初始场景）
- `scripts/verify.ts` 端到端规则断言
